## What I learned

### Running a script: two ways
- bash file.sh : I start bash and tell it to read the file.
  No execute permission needed; shebang ignored.
- ./file.sh    : Linux runs the file as a program.
  Needs execute permission (x); Linux uses the shebang.
- ./ tells bash where the file is: bash only searches the PATH
  folders, not the current folder. . = this folder.
- The shebang (#!/bin/bash, line 1) picks the program.
  Linux ignores the .sh ending.

### WSL: /mnt/c vs ~
- ~ = /home/bashar (Linux side). /mnt/c = my C: drive.
- Bash only finds a file in the folder I'm in, or by its path.
- Files on /mnt/c show rwxrwxrwx: Windows has no Linux
  permissions, so WSL makes everything fully open.
  That's why ./ worked without chmod.
- rwx is read in three groups: owner / group / others.

### Files
- cp SOURCE DESTINATION: last item is always the destination.
  The source is file + location in one path (notes/a.md).
- More than two items: all but the last are sources.
  A stray . became a second source and tried to copy the folder.
- -r = recursive, only for folders.
- mv works the same, but the original doesn't stay.
  mv also renames: mv a.md b.md.
- cp/mv overwrite without asking; -i asks first.
- rm is permanent. Check pwd before deleting.
- rmdir only deletes empty folders (safe).

### Variables and inputs
- name=value, no spaces around =, fills a variable.
- $name gives the value; without $ it's just the word.
- $1 = first word after the script name, $2 = second.
- Empty input = empty variable. Bash doesn't warn.
- = vs space: name=x fills a variable; command $name runs a
  command on the value. "id= $name" made id empty and ran
  the name as a command (exit 127 = command not found).

### Exit status
- Every command reports a number: 0 = worked/yes,
  anything else = failed/no.
- $? = the number from the LAST command only.
  Check it right after the command, at the prompt.
- id bashar -> 0, id sara -> 1. Usernames are case-sensitive.

### if
- if always checks an exit status: 0 runs then, else runs else.
- Structure: if / then / else / fi (fi closes it).
- No empty branches: an empty else gives "unexpected token fi".
- [ -z "$name" ] is a test command: "is it empty?" Yes = 0.
  Spaces inside [ ] are required; quotes keep it working
  when empty.
- exit 1 stops the script and reports failure.
  Plain exit reports 0 (success), which is wrong for an error.
- Each if is a checkpoint. Anything above the checkpoint runs
  every time; anything below an exit only runs if it passed.

### Git
- git add . adds everything new or changed below this folder.
  Safer: git add <file>, and git status before committing.
- Commit messages should say what changed.
